## Goal

Add working client-side search to the static Astro site so a reader can find a term, chapter, source, or glossary entry by typing a query. This is a Phase 4 launch-gate item (ROADMAP Phase 2 checklist: "Wire Pagefind client-side search — needed for Phase 4 launch").

"Done" = a `/search/` page with a live search box that returns real results after `npm run build && npm run preview`, the `dist/pagefind/` bundle is generated by the build, a "Search" entry exists in the header nav, and `deploy.sh` still works unchanged.

## Approach (locked)

Use the **`astro-pagefind`** integration — NOT raw `pagefind` + a manual postbuild script.

Why: it runs Pagefind automatically during `astro build` (so `npm run build`, `deploy.sh`, and a future CF GitHub auto-deploy all keep working with no script changes), supports dev-mode search after a build, and ships a drop-in `<Search>` component. One devDependency.

- Astro 5, static. `astro.config.mjs`: `trailingSlash: "always"`, `build.format: "directory"`, `site: "https://equitylanguagecommons.org"`, has a `vite.server.allowedHosts` block (Tailscale). Do not remove the allowedHosts block.

- Pages: `terms/[slug]` (renders `<h1>{term.data.term}</h1>`), `chapters/[chapter]`, `sources/[slug]`, `sources/index`, `terms/index`, `glossary`, `about`, `contribute`, `index`, `404`.
- No Pagefind anything yet. Tree clean, on `main`.

## Indexing scope decision

Index **content/detail pages only**, not listing/utility pages — keeps results clean.

INDEX (add `data-pagefind-body`):
- Term detail pages — add to the `<article>` in `TermLayout.astro` (covers every term page).
- Chapter detail page — `chapters/[chapter].astro` main content.
- Source detail page — `sources/[slug].astro` main content.
- Glossary — `glossary.astro` (long-tail value).

DO NOT index (no `data-pagefind-body`): `index` (home), `terms/index`, `sources/index`, chapters listing, `about`, `contribute`, `404`.

Also add `data-pagefind-ignore` to `Header.astro` and `Footer.astro` so site chrome never leaks into results/excerpts.

Optional, only if quick and clean: on term pages add `data-pagefind-filter="chapter:<chapter name>"` so the UI can offer a chapter filter. If it adds any complexity, SKIP it for v1 and note it.

## Tasks (one slice)

1. `cd site && npm install -D astro-pagefind`
2. `astro.config.mjs`: import `pagefind from "astro-pagefind"`, add `integrations: [pagefind()]`. Keep all existing config (site, trailingSlash, build.format directory, vite.server.allowedHosts) intact.
3. Add `data-pagefind-body` to the content wrappers listed above. Add `data-pagefind-ignore` to Header + Footer.
4. Create `src/pages/search.astro`: a normal page using `BaseLayout`, with a heading and the `<Search>` component from `astro-pagefind/components/Search`. Style it to sit naturally in the page (reuse existing global styles / classes where possible; minimal scoped CSS otherwise). Page title "Search".
5. Add `{ href: "/search/", label: "Search" }` to `navItems` in `Header.astro` (place it sensibly — e.g. right after Home, or at the end before About; pick one, keep it clean).
6. Verify: `npm run build` (must succeed and produce `dist/pagefind/`), then `npm run preview`, load `/search/`, confirm typing a known term (e.g. "latino" or "ableism") returns results that link to the right term page.
7. Commit. Suggested split: commit A = integration + indexing scope (tasks 1–3), commit B = search page + nav + verify (tasks 4–6). Per-task commits on `main` are fine.
