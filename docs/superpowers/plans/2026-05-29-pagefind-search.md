## Goal

Add working client-side search to the static Astro site so a reader can find a term, chapter, source, or glossary entry by typing a query. Phase 4 launch-gate item (ROADMAP Phase 2: "Wire Pagefind client-side search — needed for Phase 4 launch").

"Done" = a `/search/` page with a live search box that returns real results after `npm run build && npm run preview`; the `dist/pagefind/` bundle is generated by the build; a "Search" link exists in the header nav; and `./scripts/deploy.sh` still works unchanged (it calls `npm run build`).

## Approach (locked)

Use the **`astro-pagefind`** integration — NOT raw `pagefind` + a manual postbuild script.

Why: it runs Pagefind automatically during `astro build`, so `npm run build`, `deploy.sh`, and a future CF GitHub auto-deploy all keep working with zero script changes. It serves a prebuilt index in `astro dev`, and ships a drop-in `<Search>` component. One devDependency.

Install + config (verified against astro-pagefind README, 2026-05-29):

```bash
cd site && npm install -D astro-pagefind
```
```js

// ...

```

## Indexing scope — do it in BaseLayout, not per-page

Pagefind indexes `<body>` by default. We want **content/detail pages only** in results, not listing/utility pages, and never the nav/footer chrome. The clean, single-point-of-control way:

1. In `BaseLayout.astro`, add an optional prop `pagefind?: boolean` (default falsey). On the `<main>`, render the body marker only when set:
   `<main class={mainClass} data-pagefind-body={pagefind ? true : undefined}>` — in Astro, an attribute set to `undefined` is omitted, and `true` renders the bare `data-pagefind-body` attribute.
2. Pass `pagefind` from the **four content page types only**: `terms/[slug].astro`, `chapters/[slug].astro`, `sources/[slug].astro`, `glossary/index.astro`. (Add `pagefind` to their `<BaseLayout ...>` opening tag.)
3. Do **not** pass `pagefind` on: `index`, `about`, `contribute`, `chapters/index`, `sources/index`, or the new `/search/` page. Those stay out of the index.
4. Add `data-pagefind-ignore` to the root element of `SiteHeader.astro` and `SiteFooter.astro` so chrome never pollutes excerpts/results.

Optional, only if quick + clean: on `terms/[slug].astro` add `data-pagefind-filter="chapter:<category label>"` to the article so the UI can offer a chapter filter. If it adds any friction, SKIP for v1 and note it in your report.
